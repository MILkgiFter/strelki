# Умная папка для игры с Claude Code

## Что здесь

```
CLAUDE.md                  «мозг»: цикл, маршрутизация задач, экономия токенов, правила
SPEC.md                    что за игра (заполняешь ты)
PLAN.md                    где мы и что дальше (ведёт агент)
docs/GRAPHICS.md           лестница инструментов для графики и звука (читается только по делу)
.claude/settings.json      запрет читать мусор (node_modules, dist, lock, .env) + разрешённые безопасные команды
.claude/agents/
  architect.md  (opus)     только сложное: план этапа/механики, баг после 2 неудач
  reviewer.md   (sonnet)   баги и сверка со SPEC, код не трогает
  playtester.md (sonnet)   запускает игру, консоль, скриншоты
  artist.md     (sonnet)   спрайты, UI, анимации, звук по лестнице инструментов
  researcher.md (haiku)    документация, библиотеки, свободные ассеты
.claude/commands/
  next-step.md             /next-step: следующий шаг по полному циклу
  lesson.md                /lesson: ошибку превратить в правило
  polish.md                /polish: один круг доводки (можно /loop /polish)
```

Создай сам: `assets/` (+ `README.md` со списком), `refs/` (референсы), `assets/CREDITS.md`, `assets/incoming/`.

## Как устроен «мозг»

```
              ты: «ок», ответы, картинки
                        │
                        ▼
     ВЕДУЩИЙ (opusplan: план на Opus, код на Sonnet)
        │
        ├─ architect  (opus)   сложное: этап, механика, упорный баг
        ├─ Explore    (haiku)  «где в коде X?»
        ├─ researcher (haiku)  2 неудачи / библиотека / свободные ассеты
        ├─ artist     (sonnet) вся графика и звук
        ├─ playtester (sonnet) ┐ в конце этапа,
        └─ reviewer   (sonnet) ┘ параллельно
```

Модель выбирается под задачу автоматически:
- **Haiku** (дешёвая) ищет: код, документацию, ассеты.
- **Sonnet** (средняя) делает: пишет код, тестирует, ревьюит, рисует.
- **Opus** (дорогая) думает только когда нужно: в режиме плана (`opusplan`) и через `architect`.

## Почему не «выжрет» лимит

- `CLAUDE.md` короткий, а подробности (`docs/`) читаются только когда нужны.
- Агенту **запрещено** читать `node_modules`, сборку и lock-файлы. Именно они обычно съедают лимит.
- Скриншоты уменьшенные и только когда важен визуал; сначала проверяется консоль.
- Подагенты не вызываются для мелочей, ревью делается раз на этап.
- Короткие отчёты в чат, без простыней кода.
- Новая сессия на каждый этап, нить держит `PLAN.md`.

**Сам тоже экономь:**
- В проекте уже стоит `"model": "opusplan"` (`.claude/settings.json`). Новые сессии в этой папке сами планируют на Opus и пишут код на Sonnet. Если в меню модели выбрать другую модель вручную, твой выбор важнее этой настройки.
- Крупную задачу начинай с режима плана (Shift+Tab или «Plan» в меню режима): там думает Opus, а после твоего «ок» выполняет Sonnet.
- Не держи одну сессию весь день. Закончил этап, открывай новую.

## Если не получается графика

Агент сам поднимается по лестнице из `docs/GRAPHICS.md`:

1. готовые ассеты из `assets/`;
2. графика кодом (SVG, canvas, твины, частицы);
3. скрипты (SVG→PNG, спрайт-листы, @2x);
4. свободные паки (Kenney, OpenGameArt, game-icons) после твоего «ок» на скачивание;
5. AI-генерация: агент пишет готовый промпт в `docs/art-prompts.md`, ты генерируешь картинку в своём сервисе и кидаешь в `assets/incoming/`, агент нарезает и встраивает;
6. если и это не помогло, честно говорит, что не так, и предлагает упростить стиль.

На каждой ступени делается максимум 2 круга правок, потом переход дальше.

## Как начать

1. Положи всё в папку с игрой.
2. Заполни `SPEC.md` и раздел «Стек» в `CLAUDE.md`, закинь референсы в `refs/`.
3. Первое сообщение в новой сессии (лучше на Opus):
   > Прочитай CLAUDE.md, SPEC.md, PLAN.md, refs/. Задай вопросы по неясному в SPEC. Предложи уточнённый PLAN.md: маленькие шаги, у каждого проверяемый критерий. Код не пиши, жди «ок».
4. Дальше (можно на Sonnet): `/next-step`, шаг за шагом.

## Доводка до идеала: `/polish`

Один запуск: агент играет, находит **одно** самое ценное улучшение (баг → понятность → ощущение → внешний вид → мелкая фича), делает его, проверяет и записывает в `PLAN.md → Журнал полировки`.

- Вручную: `/polish` или `/polish сделай звуки поприятнее`.
- По кругу: `/loop /polish` — агент сам выбирает паузы между кругами. Останови, когда он скажет, что дальше нужны твои решения.
- Правила игры, новые зависимости и удаление фич агент **не трогает без тебя** — пишет вопрос в `SPEC.md`.
- Экономия: один круг ≈ одна маленькая правка; `playtester` зовётся только каждый 5-й круг.

## Полезные фразы

| Ситуация | Что написать |
|---|---|
| Новый этап | новая сессия → «Прочитай PLAN.md, предложи план этапа, жди ок» |
| Повторилась ошибка | `/lesson стрелки проходят сквозь друг друга` |
| Не нравится графика | «Отдай artist: сравни с refs/2.png, исправь 3 главных отличия» |
| Агент застрял | «Стоп. Отдай researcher, сам не чини» |
| Перед «готово» | «reviewer и playtester параллельно, покажи коротко» |
| Хочешь решить сам | «Дай 2–3 варианта с плюсами и минусами, не реализуй» |
